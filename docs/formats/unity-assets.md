# unity-assets: how the game's data is read

`crates/unity` (`unity-assets`) reads the player's Bopl Battle install
(Unity **2022.3.60f1**, Mono, Windows player): the SerializedFiles in
`BoplBattle_Data` (`globalgamemanagers`, `globalgamemanagers.assets`,
`resources.assets`, `sharedassetsN.assets`, `levelN`, and
`Resources/unity default resources` / `unity_builtin_extra`), their
resource streams (`*.resS` for textures, `*.resource` for audio) and
nothing else. The game ships no asset bundles and no Unity Localization
tables. The crate was copied from rounds-port (Unity 2022.3.34f1), which uses
the same serialization format; every layout was re-checked against this
game's files (see "Validation").

## SerializedFile (format 22, Unity 2022.3)

`crates/unity/src/serialized.rs`. All 263 files of the game are format 22.

**Header** (big-endian):

- legacy `u32` metadata size, `u32` file size, `u32` format, `u32` data offset
- `u8` endianness, then 3 reserved bytes
- format ≥ 22 only: `u32` metadata size, `i64` file size, `i64` data offset,
  `i64` reserved

**Metadata** (little-endian in this build):

- Unity version string, `i32` platform, `bool` type-tree flag (false in
  player builds)
- types: `i32` class id, `u8` stripped, `i16` script type index, a 16-byte
  script hash for MonoBehaviours, a 16-byte type hash
- objects: aligned to 4, then `i64` path id, `i64` byte start, `u32` size,
  `i32` type index
- script types: `i32` file index, aligned `i64` path id. These are PPtrs to
  `MonoScript`s.
- externals: empty string, 16-byte GUID, `i32` type, path
- reference types: same layout as the types (none in this game)
- user info string

**PPtrs**: `file_id` 0 is the same file. `file_id` n points into
`externals[n-1]`, resolved by file name inside `BoplBattle_Data` (or
`BoplBattle_Data/Resources` for `unity default resources` and
`unity_builtin_extra`).

Embedded type trees (blob form, with Unity's built-in string table in
`common_strings.rs`) are parsed when a file has them; player files do not.

## Type trees

The build ships without type trees, so we embed them:

- `crates/unity/typetrees/engine.json`: the 80 engine classes the game files
  use (plus a list the importer always needs), taken from UnityPy's TPK
  database for 2022.3.60f1.
- `crates/unity/typetrees/scripts.json`: every MonoBehaviour class used by
  the data (211: the game's own scripts in `Assembly-CSharp`, TextMeshPro,
  uGUI, the Input System), generated by TypeTreeGenerator from the game's
  managed DLLs. Script entries hold only the fields after the MonoBehaviour
  header. The reader prepends the engine header, which aligns after
  `m_Enabled`; the generator's header does not.

Both files hold only layouts (field names, types, alignment flags), no data
from the game's assets, and are committed, as in rounds-port: a layout is
our derived description of how to parse the files, needed at run time on
the player's machine, which has no Python tooling. To regenerate them (after
a game update; needs `tools/venv` with UnityPy and TypeTreeGeneratorAPI):

```
source env.sh && python -I scripts/dev/gen_typetrees.py
```

Each node is `[level, type, name, (byte_size,) meta_flags]`, listed in
pre-order. The interpreter (`typetree.rs`) follows Unity's binary rules:

- Primitives are stored unaligned.
- `string` is an `i32` length followed by the bytes, then always aligned.
- A node whose first child is `Array` is an array: an `i32` count, then that
  many elements. `UInt8`/`char` arrays become bytes.
- `TypelessData` is an `i32` length followed by raw bytes.
- Meta flag `0x4000` on a node, or on its `Array` child, aligns the stream
  to 4 bytes afterwards.
- `ReferencedObjectData` payloads are typed by the sibling
  `ReferencedManagedType` (unused here: the game has no
  `[SerializeReference]` fields).

TypeTreeGenerator labels `string[]` fields as `string` with an `Array` of
strings beneath, so a `string` node counts as a plain string only if its
array holds `char` (`LocalizationTable.en` etc. depend on this).

The game's fixed-point type `Fix` serializes as a struct with one `SInt64
m_rawValue` (Q32.32), `Vec2` as two `Fix` (`x`, `y`). The reader keeps them
as integers; nothing is converted to float.

## Validation

`cargo run --release -p unity-assets --example validate` reads every object
of every file (48,502 objects) and compares the results with `ref/dump`
(UnityPy 1.25 with TypeTreeGenerator, `scripts/dev/dump_assets.py`).
Result (2026-10-17): every object consumes exactly its stored size;
48,495 are equal to the dump; 6 have no usable reference because UnityPy
fails on them ("read_str out of bounds": the `LocalizationTable` asset and
the five `KeyBindButton` components of the character select scenes); we
read those exactly. The one mismatch is `InputSettings.m_SupportedDevices`, a
`string[]` that UnityPy reads as a string (the generator labelling above);
our read consumes the object exactly. `m_Script` is not compared (the dump
reads it 3 bytes early).

The importer's output is validated against the same dump by
`cargo run --release -p bopl-import --example validate_import` (see
`docs/formats/import.md`).

A unit test (`env.rs`, skipped without `BOPL_GAME_DIR`) checks format 22,
the Unity version, the 130 build scenes and exact reads of a level.

## Textures

`texture.rs` decodes the first mip level to RGBA8 and flips the rows so
they run top-down. Supported formats: DXT1, DXT5, BC4, BC5, BC7, RGBA32,
ARGB32, BGRA32, RGB24, RGB565, ARGB4444, RGBA4444, Alpha8, R8 and RG16. Image
data is inline (`image data`) or in `m_StreamData` (`.resS`).

Bopl Battle uses BC7 (69 textures, most of the art), RGBA32 (59), Alpha8
(27), DXT5 (16), DXT1 (5), RGB24 (2) and R8 (2). BC7 blocks are decoded with
the `bcdec_rs` crate (MIT, a pure-Rust port of bcdec). Alpha8 becomes white
with alpha. 10 textures are 0x0 (atlases of dynamic TMP fonts and legacy
font textures, filled at run time) and are skipped.

Checked against UnityPy's decoder (`texture2ddecoder`) for all 166
textures in these formats: maximum difference 1 per channel (rounding).

## Audio: FSB5 Vorbis → Ogg

`audio/`. `AudioClip.m_Resource` points into `sharedassets0.resource`, each
slice being an FSB5 bank with one Vorbis sample:

- **Bank header**: `"FSB5"`, version, counts, section sizes, codec (15 =
  Vorbis), padded to 60 bytes (version 1) or 64 bytes (version 0).
- **Sample header**: a `u64` bit field holding the frequency index, the
  channel code, the data offset / 32 and the sample count, followed by
  chunks. Chunk 11 holds the CRC32 of the Vorbis setup header, which FMOD
  stripped.
- **Sample data**: `u16` packet length followed by the packet, repeated.

The remux:

1. Build the Vorbis identification header (block sizes 256 and 2048) and a
   comment header.
2. Look up the setup header by CRC32 in `data/fsb5_vorbis_setup.bin`: 161 FMOD
   setup headers converted from the MIT/Apache-2.0 `fsbex` crate by
   `scripts/dev/gen_fsb_vorbis_setup.py`. This is FMOD codec data (standard
   libvorbis encoder setups, BSD-3-Clause), not game content.
3. Parse the setup header's mode table, using a small forward parser over
   codebooks, floors, residues and mappings.
4. Compute granule positions from each packet's block size. A packet adds
   prev/4 + cur/4 samples, and the first packet adds none. The final granule
   is clamped to the FSB sample count.
5. Write Ogg pages of about 4 KiB.

The audio is never re-encoded.

**Validation**: `cargo run --release -p unity-assets --example audio_check`
converts all 121 clips (46.9 MB of Ogg) and decodes each with lewton:
channels and rate match, and the last granule equals the FSB sample count
(`m_Length × rate`, worst difference 0.0000 s).

## API sketch

```rust
let dir = unity_assets::AssetDir::open(game_dir)?;      // game or data dir
let f = dir.file("level6")?;                            // lazily mmapped
for info in f.objects_of(114) {                         // MonoBehaviours
    let r = dir.read_object(&f, info)?;                 // Value tree + script
    if r.script.as_ref().is_some_and(|k| k.class == "FixTransform") {
        let x = r.value.path("_position.x.m_rawValue").i64(); // Q32.32 bits
    }
}
let tex = unity_assets::classes::Texture2D::from_value(&dir.read(&f, pid)?);
let rgba = unity_assets::texture::decode(tex.format, tex.width, tex.height, data)?;
```
